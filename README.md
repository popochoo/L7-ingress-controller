# High-Performance L7 Ingress Controller with Traffic Mirroring

Высокопроизводительный и легковесный L7 Ingress Controller (API Gateway) на языке Go с поддержкой декларативной конфигурации, «горячей» перезагрузки (Hot Reload), встроенным Rate Limiting (Token Bucket) и отказоустойчивым асинхронным зеркалированием трафика (Traffic Shadowing) на основе паттерна Backpressure.

## 🚀 Ключевые особенности и архитектура

- **Высокопроизвидительный L7-роутинг:** Маршрутизация на основе префиксного дерева (_Trie/Radix Tree_) с поддержкой алгоритма _Longest Prefix Match_. Скорость поиска составляет O(K), где K — длина URL, и не зависит от общего количества правил.
- **Hot Reload (Нулевой downtime):** Мониторинг изменений файла конфигурации через подсистему ядра ОС (`fsnotify`). Обновление правил маршрутизации в памяти происходит атомарно с помощью Lock-free примитивов (`sync.Atomic`), исключая разрыв активных соединений.
- **Безопасное асинхронное зеркалирование:** Дублирование выбранного процента трафика в тестовые среды/ML-модели через изолированный пул воркеров (_Worker Pool_).
- **Гарантия изоляции (Backpressure):** Использование неблокирующего выбора (`select default`) при отправке задач в очередь зеркалирования. Если тестовый контур начинает лагать или падает, зеркальный трафик принудительно сбрасывается (_Drop Rate_), защищая оперативную память шлюза от утечек (OOM) и сохраняя Latency основного клиента.
- **Подсистема наблюдаемости:** Сбор и автоматический экспорт метрик (RPS, Latency, Error Rate, Volume Mirrored, Drop Rate) в связку **Prometheus + Grafana** для визуализации в реальном времени.

## 🛠️ Быстрое развёртывание тестовой среды

Вся инфраструктура для тестирования (Ingress-контроллер, стабильный Production-бэкенд, искусственно замедленный Test-бэкенд, серверы Prometheus и Grafana) контейнеризирована и поднимается одной автоматической командой.

### Требования

- Docker / Docker Desktop
- Утилита `make` (установленная в вашей OS / Git Bash)

### Запуск инфраструктуры и нагрузочных тестов

Выполните в терминале команду:

```bash
make ingress-test-run
```

**Что произойдет автоматически:**

1. Соберутся оптимизированные Go-образы (Multi-stage build).
2. Запустятся прокси-сервер, бэкенды, Prometheus и Grafana.
3. Контейнер `load-generator` автоматически запустит утилиту `wrk`, которая сымитирует поток пользователей в **200 параллельных соединений** в течение 10 секунд.
4. По завершении теста в консоль выведется финальный отчет производительности, а контейнеры останутся активны в фоне для анализа графиков.

Для остановки всех сервисов и очистки сети Docker выполните команду:

```bash
make ingress-test-down
```

## 📊 Результаты нагрузочных испытаний (wrk + Grafana)

Под жесткой синтетической нагрузкой при полностью заблокированном тестовом контуре (искусственная задержка ответа тест-бэкенда составляет **2500 мс**) разработанный прототип показал следующие результаты:

- **Пропускная способность (Throughput):** `~4410 Requests/sec` (успешно обработано `44 484` запроса за 10 секунд).
- **Среднее время ответа (Average Latency):** всего `83.81 ms` для конечного пользователя, несмотря на критические задержки в зеркальном контуре.
- **Эффективность Backpressure:** Метрика `ingress_dropped_requests_total` зафиксировала ровно `44 534` сброшенных запроса. Механизм неблокирующего отбрасывания пакетов полностью защитил оперативную память шлюза от переполнения (OOM).

## 📈 Веб-интерфейсы и Мониторинг

После успешного выполнения тестов данные телеметрии доступны на локальном хосте по следующим адресам:

1. **Grafana Дашборд (Визуализация):** [http://localhost:3000](http://localhost:3000)
   - _Логин/Пароль:_ `admin` / `admin`
   - _Доступные панели:_ График входящего RPS, перцентили сквозных задержек (p50, p95, p99), динамическая скорость сброса трафика Backpressure Drop Rate.
2. **Prometheus UI (База данных):** [http://localhost:9093](http://localhost:9093)
   - Позволяет выполнять прямые PromQL-запросы к метрикам ингресса (например: `ingress_dropped_requests_total`).
3. **Эндпоинт сырых метрик Ингресса:** [http://localhost:9090/metrics](http://localhost:9090/metrics)

## 📂 Структура проекта

```text
├── cmd/
│   ├── ingress/          # Точка входа Ingress Controller (main.go)
│   └── mock_backends/    # Сервера-заглушки (Production и Slow Test)
├── internal/
│   ├── config/           # Модуль парсинга YAML и Hot Reload (fsnotify)
│   ├── router/           # Префиксное дерево маршрутизации (Trie Tree)
│   ├── proxy/            # Reverse Proxy, Rate Limiter и Fallback-логика
│   ├── mirror/           # Ограниченный Worker Pool для зеркалирования
│   └── metrics/          # Экспорт кастомных метрик в Prometheus
├── config.yaml           # Декларативная конфигурация шлюза
├── prometheus.yml        # Конфигурация сборщика метрик Prometheus
├── docker-compose.yaml   # Инфраструктурный манифест всей тестовой среды
└── Makefile              # Команды автоматизации (сборка, запуск, тесты, очистка)
```
