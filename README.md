# High-Performance L7 Ingress Controller with Traffic Mirroring

Высокопроизводительный и легковесный L7 Ingress Controller (API Gateway) на языке Go с поддержкой декларативной конфигурации, «горячей» перезагрузки (Hot Reload), встроенным Rate Limiting (Token Bucket) и отказоустойчивым асинхронным зеркалированием трафика (Traffic Shadowing) на основе паттерна Backpressure.

## 🚀 Ключевые особенности и архитектура

- **Высокопроизводительный L7-роутинг:** Маршрутизация на основе префиксного дерева (_Trie/Radix Tree_) с поддержкой алгоритма _Longest Prefix Match_. Скорость поиска составляет O(K), где K — длина URL, и не зависит от общего количества правил.
- **Hot Reload (Нулевой downtime):** Мониторинг изменений файла конфигурации через подсистему ядра ОС (`fsnotify`). Обновление правил маршрутизации в памяти происходит атомарно с помощью Lock-free примитивов (`sync.Atomic`), исключая разрыв активных соединений.
- **Безопасное асинхронное зеркалирование:** Дублирование выбранного процента трафика в тестовые среды/ML-модели через изолированный пул воркеров (_Worker Pool_).
- **Гарантия изоляции (Backpressure):** Использование неблокирующего выбора (`select default`) при отправке задач в очередь зеркалирования. Если тестовый контур начинает лагать или падает, зеркальный трафик принудительно сбрасывается (_Drop Rate_), защищая оперативную память шлюза от утечек (OOM) и сохраняя Latency основного клиента.
- **Подсистема наблюдаемости:** Сбор и экспорт метрик (RPS, Latency, Error Rate, Volume Mirrored, Drop Rate) напрямую в Prometheus/Grafana.

## 🛠️ Быстрое развёртывание тестовой среды

Вся инфраструктура для тестирования (Ingress-контроллер, стабильный Production-бэкенд, искусственно замедленный Test-бэкенд и сервер Prometheus) контейнеризирована и поднимается одной командой.

### Требования

- Docker
- Docker Compose

### Запуск инфраструктуры и нагрузочных тестов

Выполните в терминале команду:

```bash
docker-compose up --build
```

**Что произойдет автоматически:**

1. Соберутся оптимизированные Go-образы (Multi-stage build).
2. Запустятся прокси-сервер, бэкенды и Prometheus.
3. Контейнер `load-generator` автоматически запустит утилиту `wrk`, которая сымитирует поток пользователей в **200 параллельных соединений** в течение 10 секунд.
4. По завершении теста в консоль выведется финальный отчет производительности.

## 📊 Результаты нагрузочных испытаний (wrk + Prometheus)

Под жесткой синтетической нагрузкой при полностью заблокированном тестовом контуре (искусственная задержка ответа тест-бэкенда составляет **2500 мс**) разработанный прототип показал следующие результаты:

- **Пропускная способность (Throughput):** `~4410 Requests/sec` (обработано `44 484` запроса за 10 секунд).
- **Среднее время ответа (Average Latency):** `83.81 ms` для конечного пользователя, несмотря на задержки в зеркальном контуре.
- **Эффективность Backpressure:** Метрика `ingress_dropped_requests_total` зафиксировала ровно `44 534` сброшенных запроса. Система успешно защитила буфер памяти от переполнения.

### Просмотр графиков

После выполнения теста откройте веб-интерфейс Prometheus:

```text
http://localhost:9093
```

Введите в поле поиска метрику `ingress_dropped_requests_total` и перейдите на вкладку **Graph**, чтобы увидеть график работы механизма сброса трафика.

## 📂 Структура проекта

```text
├── cmd/
│   ├── ingress/          # Точка входа Ingress Controller (main.go)
│   └── mock_backends/    # Сервера-заглушки (Production и Slow Test)
├── internal/
│   ├── config/           # Модуль парсинга YAML и Hot Reload (fsnotify)
│   ├── router/           # Префиксное дерево маршрутизации (Trie Tree)
│   ├── proxy/            # Reverse Proxy, Rate Limiter и Fallback-логика
│   ├── mirror/           # Ограниченный Worker Pool для зеркалирования
│   └── metrics/          # Экспорт кастомных метрик в Prometheus
├── config.yaml           # Декларативная конфигурация шлюза
├── prometheus.yml        # Конфигурация сборщика метрик
└── docker-compose.yaml   # Инфраструктурный манифест среды
```
